# 레벨 디자인 가이드 (사이드뷰 플랫포머)

현대 닌텐도 2D 플랫포머(NSMB / Wonder 계열)의 **방법론**만 참고한다. 이름·캐릭터·아트·음악·레벨·상징 오브젝트는 절대 가져오지 않는다 (금지 목록: `PLATFORMER_DESIGN.md` 첫 단락). 이 게임의 어휘: Fizz(재화), Catnap Cushion(체크포인트), Memory Door(골), Memory shard(레벨당 3개), Cork(기본 적), 끈적한 주스 웅덩이, 지하 저장고 팔레트.

비주얼은 전부 플레이스홀더다. 레벨 작업의 기준은 **레이아웃·리듬·가독성·가르치기**이며, 아트 교체(각 킷 노드의 `Visual` 자식 교체, 타일 아틀라스 교체) 후에도 레이아웃은 그대로 유효해야 한다.

---

## 1. 방법론

### 1.1 한 레벨 = 한 아이디어
레벨마다 핵심 아이디어를 **한 문장**으로 쓴다. 그 레벨의 모든 장애물은 이 아이디어의 변주다. 새 요소를 넣고 싶으면 다음 레벨로 미룬다.
> 예: "끈적한 주스 웅덩이는 달리기와 점프를 줄이고, 깨끗한 선반에서는 대시가 몸을 실어 준다."

### 1.2 4비트 구조
| 비트 | 목적 | 규칙 |
|---|---|---|
| **Introduce** | 아이디어를 안전하게 보여 준다 | 첫 만남은 평평하고 안전한 바닥 위. 실패해도 잃는 것이 없다 |
| **Develop** | 아이디어를 기존 동작(점프·대시·적)과 조합 | 한 번에 변수 하나씩 추가 |
| **Twist** | 같은 아이디어를 새 관점으로 (리듬, 수직, 역이용) | 새 "규칙"이 아니라 같은 규칙의 새 상황 |
| **Finale** | 앞에서 배운 것만으로 구성된 시험 | **새 요소 금지**. 연속 배치로 긴장감만 올린다 |

비트 사이에는 **브레더**(위험 없는 짧은 평지, 보상, 경치)를 둔다. 전체 2–4분, **체크포인트는 약 50 %** 지점의 브레더에, 골 직전에는 깨끗한 **런웨이**.

### 1.3 텍스트 없이 가르치기
- 위험 요소의 첫 등장은 **실패 비용이 0**인 곳 (구덩이 없는 평지의 웅덩이).
- 카메라가 다음 도전을 **먼저** 보여 준다: 착지점이 화면 안에 있어야 한다 (가로 27타일 중 플레이어 앞 ~16타일).
- 위험 → 해결 수단 순서가 아니라, **해결 수단을 쓰게 되는 상황 → 그 수단이 꼭 필요한 상황** 순서.

### 1.4 유도 (Guidance)
- **Fizz 트레일** = 점프 궤적 그리기. 아치(`shape = ARC`)는 "여기서 이렇게 뛰어라", 수평선(`LINE`)은 "여기서 대시", 수직선은 "아래로 내려가라 / 아래에 뭔가 있다".
- 시크릿 힌트: 다른 재질(드롭스루 선반 판자), 거미줄 데코, 전경 상자 틈으로 비치는 반짝임.
- 랜드마크 데코(창문, 통)는 비트의 시작/체크포인트를 알려 주는 용도로만 아껴 쓴다.

### 1.5 위험–보상
- shard 3개 = **온패스**(진행 중 자연스럽게) / **스킬**(본선 밖, 더 어려운 동작) / **히든**(SecretArea).
- 스킬 shard는 "정확한 위치 + 정확한 동작"을 요구하고, **플레인 점프로는 절대 닿지 않게** 테스트로 고정한다.
- 보상 Fizz는 위험한 궤적(가시 구덩이 위 대시 높이)에 둔다.

### 1.6 페이싱
- 긴장 구간 15–25초 → 브레더 3–5초.
- 같은 장애물은 3회 이내 반복, 반복마다 한 가지만 바꾼다(거리, 높이, 타이밍, 적).
- 리듬 장애물(DripEmitter)은 대기 시간이 2초를 넘지 않게: on/off 각 1.6–2.0 s, 텔레그래프 0.6 s.

## 2. 메트릭 (16 px 타일, 실측)

`tests/unit/test_player_metrics.gd`, `tests/unit/test_level_cellar_metrics.gd`가 실제 모터로 측정해 출력한다. 설정이 바뀌면 이 표를 다시 채운다.

| 동작 | 깨끗한 바닥 | 끈적한 웅덩이 (speed 0.55 / jump 0.75) |
|---|---|---|
| 달리기 속도 | 180 px/s | 99 px/s |
| 최고점 (점프 유지) | **4.58 타일** (73 px) | **2.56 타일** (41 px) |
| 최소 홉 (탭) | 1.1 타일 | – |
| 제자리 점프 거리 | 8.4 타일 | 5.95 타일 |
| 달리기 점프 거리 | 9.2 타일 | 6.56 타일 |
| 달리기 점프 + 정점 공중 대시 | **14.0 타일** | **11.56 타일** |
| 체공 시간 | 0.82 s (대시 시 1.0 s) | – |

참고: 대시는 0.18 s 동안 중력 0, 420 px/s (≈4.7 타일), 지상 대시는 웅덩이 영향을 받지 않는다. 웅덩이 판정은 바닥 위 7 px까지라 점프 직후 수평 속도는 공중에서 180으로 회복된다 → **웅덩이의 진짜 효과는 높이**(4.58 → 2.56)다. 가장자리 여유(몸 절반 6 px + 코요테 0.12 s)로 실효 도달 거리는 표보다 약 1–1.4 타일 길다.

### 2.1 디자인 규칙
| 규칙 | 값 |
|---|---|
| 플레인 점프로 넘어야 하는 구멍 | **≤ 7 타일** (실효 9.2+ 대비 여유) |
| 첫 구덩이 | ≤ 3 타일, 깨끗한 런업 ≥ 6 타일 |
| 대시가 필요한 구멍 | **9–13 타일** (깨끗한 이륙). 끈적한 이륙이면 6 타일+고저차 2로도 "대시 필수" |
| 플레인 점프로 오르는 단차 | ≤ 4 타일 (권장 3) |
| 웅덩이 위에서는 못 오르게 할 단차 | ≥ 3 타일 (웅덩이 최고점 2.56) |
| 점프 위 머리 공간 | **≥ 4 타일** (권장 5) |
| 초반 발판 폭 | **≥ 3 타일**, 피날레도 ≥ 6 |
| 대시 스킵 방지 | "플레인 점프 전용" 구간을 건너뛰는 거리 ≥ 14 타일 + 고저차, 또는 천장. 리듬 웅덩이는 폭 ≥ 13–14 타일 (점프+대시가 3타일 높이에 닿는 거리 ≈ 12.2) |
| 원웨이 선반 사다리 | 수직 간격 3 타일, 엇갈려 폭 5 타일 |
| 드롭스루가 필요한 곳 | 페인트 타일 `=`가 아니라 **CellarShelf 노드** (타일 선반은 원웨이지만 down+jump로 못 내려감) |
| 가시 | 즉사 아님(데미지+넉백). 바닥 있는 구덩이(깊이 3)는 기어 나올 수 있게; 바닥 없는 구덩이는 KillZone |

## 3. 카메라 프레이밍 규칙

- 줌 1.5 → 약 **27 × 15 타일**. 발은 화면 높이 **70 %** 라인에 쉰다 → 발 아래 약 4.5 타일, 위로 약 10 타일 보인다.
- 수평 리드 44 px(속도 기반) → 플레이어는 진행 방향 뒤쪽 ~40 %. **착지점은 이륙점에서 16 타일 이내**에 두면 이륙 전에 보인다.
- **플랫폼 스냅**: 지상에서만 새 바닥 높이로 0.3 s 이징. 공중에선 머리가 위 22 % 위로 가거나 발이 레스트 라인+1 타일 아래로 내려갈 때만 움직인다. → 일반 점프는 화면을 흔들지 않는다. 수직 구간은 3 타일 계단으로 만들면 한 칸씩 "착, 착" 올라가는 리듬이 생긴다.
- `CameraBounds` 아래 경계는 바닥 + 5 타일 (구덩이 바닥 KillZone이 보이도록, 그 아래는 안 보이게). 위 경계는 가장 높은 천장.
- 지형 타일은 bounds 바닥보다 더 아래까지 칠한다 (빈 공간이 보이지 않게).
- 텔레포트/리스폰은 하드 스냅. 레벨 안에서 순간이동 연출이 필요하면 `teleport_distance` 이상 이동시키면 자동 스냅.

## 4. 템플릿으로 새 레벨 만들기

1. `scenes/levels/_template_side_view.tscn` 을 `scenes/levels/<id>.tscn` 으로 복제, `scripts/levels/template_side_view_layout.gd` 를 `scripts/levels/<id>_layout.gd` 로 복제 (`class_name` 변경).
2. `LevelInfo`: `level_id`, `display_name`, `shard_count`(3), 필요하면 `camera_zoom`.
3. 레이아웃 파일에서 ASCII 지형 작성 (`#` 땅, `=` 원웨이 선반, `^` 가시 아트, 데코 문자: `CellarTiles.paint_ascii` 참고). 첫 줄 = 타일 행 `MAP_TOP`, 행 0 = 메인 바닥(y = 0 px).
4. `scripts/levels/level_builder.gd` 의 `LEVELS` 에 (씬, 레이아웃) 추가 후 빌드:
   `godot --headless --path game --script res://scripts/levels/level_builder.gd`
   → World/Deco/Foreground 레이어의 `tile_map_data` 줄만 교체된다. 에디터에서 배치한 노드는 보존된다. (빌드 후 에디터에서 타일을 직접 칠해도 되지만, 다음 빌드 때 덮어써진다 — 한쪽만 원본으로 쓸 것.)
5. 에디터에서 노드 배치 (모든 위치 = 타일 × 16, 바닥 노드의 원점은 바닥면):
   - `Puddles/` StickyPuddle (`width`), `Drips/` DripEmitter (`puddles`, `on_time`, `off_time`, `phase`; 원점 = 병 입구, 손이 닿지 않는 선반 위),
   - `Hazards/` Spikes (타일 `^` 를 쓰면 `Visual` 숨김), KillZone (바닥 없는 구덩이 아래 한 장으로 레벨 전체 커버, `Visual` 숨김),
   - `Enemies/` Cork, `Pickups/` FizzTrail·MemoryShard(`index` 0/1/2), CatnapCushion(`checkpoint_id`), CellarShelf(드롭스루), SecretArea(`overlay` = Foreground 레이어), MemoryDoor (빈 `next_scene` = 허브로).
6. `Beats/` 아래 Marker2D를 비트 시작마다 하나씩(이름 = 비트 id, 위치 = 플레이어 발). 테스트와 캡처가 이걸 쓴다.
7. `CameraBounds.bounds` 를 레벨 전체로, `Spawns/Start` 와 `Player` 를 시작점에.
8. 스크린샷 리뷰 (모든 비트 + 근접 + 전체 오버뷰):
   `xvfb-run -a -s "-screen 0 1280x720x24" godot --path game --rendering-driver opengl3 --resolution 1280x720 res://scenes/levels/level_capture.tscn -- --out=/abs/dir --level=res://scenes/levels/<id>.tscn`
9. 테스트: `tests/integration/test_level_cellar_shelf.gd` 를 본떠 로드/구조 + 비트별 핵심 장애물을 실제 입력(`PlayerInputState` 오버라이드)으로 통과 + 스킬 shard의 "플레인 실패 / 대시 성공" 쌍 테스트.
10. 허브 등록: `scripts/tests/test_hub.gd` 의 `labs` 에 항목 추가 (그리고 `tests/unit/test_ui_hub.gd` 의 개수).

## 5. 작업 예시: "The Cellar Shelf"

핵심 아이디어: **끈적한 주스 웅덩이는 달리기와 점프를 줄이고, 깨끗한 선반에서는 대시가 몸을 실어 준다.**
씬 `scenes/levels/cellar_shelf.tscn`, 지형 `scripts/levels/cellar_shelf_layout.gd`, 폭 340 타일(5440 px), 높이 행 −31…+6.

| 비트 | 타일 x | 내용 | 가르치는 것 |
|---|---|---|---|
| Introduce | 0–45 | 평지 → 웅덩이(11–16) + 웅덩이 안에서 시작하는 낮은 Fizz 아치(shard 0이 정점) → 깨끗한 런업 → 2타일 구덩이(30–31) | 웅덩이는 무해하지만 느리고 점프가 낮다 / 구덩이 = 점프 |
| Develop | 46–140 | 2타일 구멍 사이 선반: A 깨끗(48–53) → B 끈적(56–65) → C 깨끗·1단 위(68–73) → D 끈적 22타일 + Cork(76–97) → **6타일 대시 구멍**(98–103, 끈적 이륙, 착지 +2단, Fizz 수평선) → E 깨끗 → 스킬 구간: 웅덩이 12 / **깨끗한 1타일(124)** / 웅덩이 16, 4타일 위 선반(133–136)에 shard 1 | 끈적 이륙은 낮다 → 대시로 거리 확보 / 깨끗한 칸에서만 최대 높이 |
| Breather | 141–169 | 3단 내려선 평지, 창문 아래 **Catnap Cushion (x 157 = 46 %)** | 쉬기, 체크포인트 |
| Twist | 170–238 | DripEmitter 2개가 14타일 웅덩이를 2 s 주기로 켰다 껐다(위상 반대) → 각 웅덩이 끝의 **3타일 단차**는 마른 순간에만 오를 수 있다 → 원웨이 선반 사다리(행 −6 → −24, 3타일 간격, 플랫폼 스냅 카메라 시연) → 천장 있는 상단 통로, **CellarShelf 드롭스루 → 전경 상자 뒤 비밀 포켓(shard 2)** → Fizz 수직선 따라 낙하 | 같은 웅덩이를 "타이밍" 관점으로 / 수직 이동 |
| Finale | 239–317 | 3개의 점프+대시 가시 구덩이: 12타일(드립 웅덩이 이륙) → 10타일 발판 + Cork → 11타일(깨끗한 이륙, 보상 Fizz) → 8타일 드립 웅덩이 발판 → 12타일 | 새 요소 없음: 마른 타이밍 + 대시 + 적 처리 |
| Runway | 318–337 | 깨끗한 직선 → **Memory Door (x 333)** → 허브 | 마무리 |

### Shard 배치
| # | 종류 | 위치 | 조건 (테스트로 고정) |
|---|---|---|---|
| 0 | 온패스 | (280, −48): 첫 아치의 정점 | 웅덩이 안에서 점프하면 지나간다. 깨끗한 점프도 통과 |
| 1 | 스킬 | (2160, −128): 깨끗한 1타일에서 8타일 떨어진 4단 위 선반 | 플레인 달리기 점프(180 px/s 강제)는 실패, 웅덩이에서 걸어 나와 깨끗한 칸에서 점프+정점 대시는 성공. 웅덩이에서는 높이 2.56 < 4라 불가 |
| 2 | 히든 | (3664, −350): 상단 통로 아래 포켓 | CellarShelf에서 down+jump로 낙하, SecretArea가 전경 상자 레이어를 투명하게. 탈출은 원웨이 선반으로 다시 점프 |

### 설계 검증 포인트 (tests/integration/test_level_cellar_shelf.gd)
- 6타일 구멍: 끈적 플레인 점프 실패 / 점프+대시 성공 (착지 +2단이 플레인 도달을 ~5타일로 줄임).
- 드립 단차: 젖었을 때 실패, 말랐을 때 성공, 젖었을 때 마른 바닥에서 점프+대시로 건너뛰기도 실패 (웅덩이 폭 14).
- 피날레 드립 구멍(12타일): 젖은 이륙은 점프+대시도 부족, 마른 이륙은 성공 → 타이밍이 의미 있다.
- 체크포인트 46 %, 리스폰 위치, 문 → `level.cellar_shelf.clear` + 허브.

### 알려진 한계 / 다음 단계
- 플레이스홀더 웅덩이 색(앰버)이 바닥 윗면 림과 비슷해 멀리서 덜 읽힌다 → 아트 교체 시 웅덩이를 더 채도 높은 색/광택으로.
- 비밀 포켓의 반짝임이 상자 틈으로 살짝 보인다 (의도된 힌트로 사용 중).
- 상단 통로에서 낙하 구간이 약 23타일 — 카메라가 자연스럽게 따라가지만, 이후 레벨에서는 중간 발판으로 끊는 것을 권장.
