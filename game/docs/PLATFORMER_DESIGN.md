# Side-View Platformer: Presentation, Feel & Level Design Brief

Reference = the *methodology* of modern Nintendo 2D platformers (New Super Mario Bros. Wii / U, Super Mario Bros. Wonder): camera behaviour, screen composition, readability, game feel and level structure.
**Do not copy** any of their names, characters, art, music, levels or iconic objects (no question-mark blocks, warp pipes, mushrooms, goomba/koopa look-alikes, flagpole, star coins look). Every asset here is original procedural placeholder art, replaced later by the team's own art.

## A. Screen methodology

### A1. Scale & framing
- Tile grid **16 px**. Side-view gameplay camera **zoom 1.5** on the 640×360 viewport → visible area ≈ 427×240 px = **~27 × 15 tiles** (modern 2D Nintendo framing is ~14–16 tiles tall). UI (CanvasLayers) is not zoomed.
- Player body ≈ 1 × 1.5 tiles → ~10 % of screen height (was ~5 %). Physics tuning (180 px/s, jump 420, gravity 1200 → apex ≈ 4.6 tiles) stays valid on the 16 px grid.
- Composition: when running, the player sits ~**38–42 %** from the trailing edge (look-ahead); standing ground sits in the **lower third**.

### A2. PlatformerCamera (side view)
- **Horizontal look-ahead**: target x = player x + facing × lead (≈ 1/6 visible width), lead eases in over ~0.4 s, so turning around does not whip the screen. Small dead zone; smoothing.
- **Vertical platform snap** (no bob on jumps): while grounded, camera y eases to the player's ground height. While airborne the camera y holds, unless the player leaves a vertical window (above ~30 % from top or below ~70 %), then it follows. Falling follows faster than rising.
- **Limits** from `CameraBounds`; `CameraZone` areas switch limits/zoom for sub-areas (secret rooms, vertical shafts) with a short blend.
- **Shake** (trauma-based, decays) + optional zoom punch; disabled by a setting. **Pixel snap** option.
- Top-down keeps a simple smoothed follow.

### A3. Readability & layering (back → front)
1. Sky gradient (2 colours).
2. Far parallax (scroll 0.1–0.2): low-contrast silhouettes.
3. Mid parallax (0.4–0.5): hills/structures, desaturated.
4. Near decoration (0.8–0.9).
5. **Playable layer** (1.0): highest contrast, outlined, **lit top rim** on walkable surfaces so "where can I stand" is instant.
6. Foreground (1.1–1.3, sparse, never hides hazards) + `SecretArea` overlay tiles that fade when entered.
- Colour language: playable = saturated + outline; background = desaturated/atmospheric; **hazards = red/white high-contrast spiky silhouettes**; collectibles = gold with sparkle; interactables pulse softly when in range.

### A4. HUD
- Minimal: top-left hearts; top-centre coin counter; top-right **3 memory-shard slots for the current level** (filled / empty outline). Debug overlays OFF by default (F3 toggles).
- Level-clear tally (time, coins, shards) on the goal screen.

### A5. Transitions
- Doors / death / level clear: **iris wipe** centred on the player; menus keep the fade.

## B. Game feel (side view)
- **Gravity shaping**: fall gravity × ~1.7; **apex hang** (gravity × ~0.5 while |vy| < ~50 px/s and jump held); jump cut on release (already present).
- **Corner correction**: a head bump within ~4 px of a ceiling edge nudges the player around it; ledge step-up ≤ 3 px.
- **Turn skid**: reversing at speed plays skid dust; acceleration curve keeps run momentum readable.
- **Stomp**: landing on a `stompable` enemy damages it and bounces the player (higher bounce while jump is held). Sword attack still works.
- **Juice**: squash & stretch on jump/land, run lean & foot cycle, blink, dash after-images, landing/jump/skid dust (CPUParticles2D), coin sparkle, **hit-stop** (~50 ms) on stomps/sword hits, small camera shake on heavy hits. All tunable / disable-able (accessibility) and off in automated tests where timing matters.
- Audio: every feel event has an AudioStreamPlayer hook (streams empty for now).

## C. Level kit (16 px grid)
- **Placeholder tileset** generated by a tool script (original art): ground with lit grass rim + dirt fill (terrain autotile: edges/corners), semisolid (one-way) platform, solid block, spikes, background deco. Physics on layer World; one-way tiles one-way. Paintable in the editor via terrain sets.
- **Components**: Coin (+trail helper), MemoryShard (3 per level, persistent flags, HUD slots), MovingPlatform (path, ping-pong/loop, carries the player), FallingPlatform (shake → fall → respawn), Spring (bounce), ItemCrate (hit from below or slash → coin/heart pop), Spikes (damage + knockback, not instant death), KillPlane (bottomless pit), Walker enemy (patrol, turns at walls/ledges, stompable + slashable), MidwayFlag (checkpoint with raise animation), GoalGate (level clear: input lock, celebration, tally, then exit), SecretArea (foreground fade + reveal sound hook), CameraZone.

## D. Level design methodology
- **One core idea per level**, developed in **four beats**: *introduce* (safe, no punishment) → *develop* (combine with known elements) → *twist* (surprising variation) → *finale* (confident mastery test), with **breathers** between beats.
- Length ≈ 2–4 min; **midway flag at ~50 %**; goal sequence at the end.
- **Teach without text**: first encounter of any hazard/enemy happens on flat safe ground; the camera reveals the next challenge before it must be solved.
- **Guidance**: coin trails trace jump arcs and hint at secrets; landmarks; gaps in rhythm signal danger.
- **Risk–reward**: 3 memory shards per level — one on the path, one off-path skill, one hidden (SecretArea / breakable wall / off-screen route).
- **Metrics** (from PlayerConfig, documented in LEVEL_DESIGN_GUIDE): max jump height/width standing vs. running vs. with dash; early platforms ≥ 3 tiles wide; ≥ 4 tiles of headroom over jumps; first pits ≤ 3 tiles.
- Deliverable: a polished **showcase level** built only from the kit + a level template scene + LEVEL_DESIGN_GUIDE.md.
